# Dia 120 — Projeto: aplicação segura e resiliente

## Objetivo
Integrar arquitetura, segurança e resiliência em um projeto completo.

## Requisitos
O projeto deve possuir:
- arquitetura em camadas ou hexagonal;
- casos de uso;
- persistência;
- validação;
- autenticação em ambiente de laboratório;
- autorização por papéis;
- auditoria;
- timeouts;
- retries limitados;
- rate limiting;
- logs;
- métricas;
- testes;
- CI;
- documentação.

## Entrega
Produza:
1. diagrama da arquitetura;
2. modelo de domínio;
3. contrato da API ou CLI;
4. matriz de permissões;
5. política de resiliência;
6. testes;
7. checklist de segurança;
8. instruções de execução.

## Critério
O projeto deve continuar funcionando de forma previsível diante de entradas inválidas, falhas temporárias e tentativas de acesso não autorizado.

## Checklist final
- [ ] Segurança foi considerada desde o desenho.
- [ ] Falhas têm comportamento definido.
- [ ] Testes cobrem cenários críticos.
- [ ] Documentação permite reproduzir o projeto.
