# Dia 106 — Casos de uso

## Objetivo
Transformar requisitos em operações explícitas da aplicação.

## Teoria
Um caso de uso representa uma ação relevante para o sistema, como criar pedido, registrar pagamento ou cancelar tarefa.

## Prática
Escolha três requisitos do projeto e transforme-os em casos de uso com:
- entrada;
- regras;
- saída;
- erros;
- dependências.

## Desafio
Escreva testes para os casos de uso antes de alterar a implementação.

## Checklist
- [ ] Casos de uso são claros.
- [ ] Regras estão identificadas.
- [ ] Erros esperados estão definidos.
