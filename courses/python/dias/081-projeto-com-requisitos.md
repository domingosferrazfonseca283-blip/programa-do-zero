# Dia 81 — Projeto com requisitos

## Objetivo
Transformar um problema informal em requisitos claros antes de escrever código.

## Teoria
Um projeto profissional começa por entender:
- quem usa o sistema;
- qual problema precisa ser resolvido;
- entradas e saídas;
- regras de negócio;
- erros esperados;
- restrições;
- critérios de aceitação.

Separar **requisito** de **implementação** evita decidir a tecnologia antes de compreender o problema.

## Exercício guiado
Escreva requisitos para um gestor de tarefas:
1. criar tarefa;
2. listar tarefas;
3. concluir tarefa;
4. remover tarefa;
5. impedir título vazio.

Depois transforme cada requisito em um critério de aceitação verificável.

## Desafio
Adicione prioridades, prazo e pesquisa sem definir ainda a implementação.

## Checklist
- [ ] Separei problema de solução.
- [ ] Escrevi regras verificáveis.
- [ ] Identifiquei entradas inválidas.
- [ ] Defini critérios de aceitação.
