# COMEÇA AQUI — Academia de Programação e Cibersegurança

Este ficheiro é a **espinha dorsal da formação**. O objetivo não é apenas ler conteúdo: é desenvolver competência verificável.

## Regra principal

A sequência de aprendizagem é:

**teoria → exemplo → prática guiada → exercício → erro → correção → repetição → desafio → projeto → revisão → avaliação → próximo nível**

Não avance apenas porque terminou de ler uma aula. Avance quando conseguir **explicar, implementar, testar e corrigir** o que estudou.

## 1. Ordem recomendada

### Fase 0 — Preparação
- computador e terminal;
- Git e GitHub;
- editor/IDE;
- organização de ficheiros;
- execução de programas;
- leitura de erros.

### Fase 1 — Python
Comece em `courses/python/`.

Percurso:
1. fundamentos;
2. programação estruturada;
3. estruturas de dados;
4. OOP;
5. testes e qualidade;
6. bancos de dados;
7. APIs e web;
8. arquitetura;
9. concorrência e performance;
10. segurança;
11. projeto profissional;
12. projeto final.

### Fase 2 — Engenharia de software
Estude em conjunto:
- Git;
- arquitetura;
- bancos de dados;
- web/APIs;
- testes;
- DevOps;
- segurança de desenvolvimento.

### Fase 3 — Outras linguagens
Depois de construir uma base sólida em programação, use os percursos de:
- JavaScript;
- Java;
- C++;
- C#;
- Go;
- Rust;
- SQL.

A meta não é decorar sintaxe. É aprender a transferir conceitos entre linguagens.

### Fase 4 — Cibersegurança
A trilha de cibersegurança deve ser estudada progressivamente:
1. fundamentos;
2. redes;
3. sistemas;
4. aplicações;
5. logs e deteção;
6. resposta a incidentes;
7. identidade e acesso;
8. cloud/DevSecOps;
9. governança e risco;
10. laboratórios defensivos;
11. projeto SOC/integrador.

Todo laboratório deve ser realizado apenas em sistemas próprios ou explicitamente autorizados.

## 2. Como estudar cada dia

Para cada aula:

1. Leia a explicação.
2. Execute todos os exemplos.
3. Reescreva pelo menos um exemplo sem copiar.
4. Resolva o exercício de fixação.
5. Resolva o desafio sem consultar a solução.
6. Registe os erros encontrados.
7. Explique com as suas próprias palavras o conceito.
8. Faça o mini-projeto.
9. Marque o checklist.
10. Só então passe para a próxima aula.

## 3. Critério de domínio

Considere um assunto dominado quando consegue:

- explicar o conceito de forma simples;
- escrever um exemplo do zero;
- reconhecer erros comuns;
- corrigir um programa;
- testar o comportamento;
- adaptar o conceito a um problema novo;
- justificar as decisões técnicas.

## 4. Projetos obrigatórios

A formação deve produzir artefactos reais, não apenas exercícios isolados.

Exemplos:
- CLI;
- gestor de tarefas;
- sistema de inventário;
- aplicação com SQLite;
- API REST;
- serviço concorrente/assíncrono;
- projeto com testes e CI;
- projeto com observabilidade;
- projeto final profissional;
- laboratório SOC defensivo.

## 5. Avaliação

Cada grande etapa deve terminar com:

- revisão;
- exercícios novos;
- avaliação sem consulta;
- correção dos erros;
- projeto;
- checklist de competências.

Se a avaliação revelar lacunas, volte ao módulo correspondente antes de avançar.

## 6. Princípio da formação

A quantidade de páginas não é o objetivo.

O objetivo é formar alguém capaz de **pensar, construir, testar, depurar, proteger, explicar e manter software**.

A dificuldade aumenta gradualmente. O aluno começa com problemas pequenos e termina trabalhando com sistemas completos.
