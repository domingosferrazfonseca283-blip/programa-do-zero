# Matriz de Competências

Esta matriz define o que deve ser demonstrado ao longo da formação.

| Área | Inicial | Intermédio | Avançado | Profissional |
|---|---|---|---|---|
| Programação | sintaxe e lógica | funções e estruturas | abstrações e concorrência | sistemas completos |
| Python | fundamentos | OOP, dados, APIs | internals, async, performance | arquitetura e produção |
| Algoritmos | busca e ordenação | estruturas de dados | grafos, árvores, DP | escolha baseada em custo |
| SQL | CRUD | joins, agregações | índices, transações | modelagem e otimização |
| Web | HTTP | REST e JSON | segurança e testes | APIs robustas |
| Testes | casos básicos | unitários/integrados | mocks, regressão, cobertura | estratégia de qualidade |
| Arquitetura | separação simples | camadas | dependências e padrões | sistemas evolutivos |
| Git | commits | branches e colaboração | revisão | fluxo profissional |
| DevOps | conceitos | CI/CD | observabilidade | entrega e operação |
| Segurança | princípios | validação e autenticação | threat modeling e hardening | segurança integrada |
| Cibersegurança | fundamentos | deteção e resposta | operações defensivas | projetos SOC e governança |
| Sistemas | processos e ficheiros | redes e serviços | concorrência | diagnóstico e operação |
| Engenharia | código funcional | organização | qualidade | manutenção de sistemas reais |

## Evidência de competência

Cada competência deve possuir evidência concreta:

- código escrito pelo aluno;
- exercício resolvido;
- teste automatizado;
- correção de bug;
- explicação técnica;
- projeto;
- revisão;
- avaliação.

## Níveis

### Nível 1 — Reconhecer
Consegue identificar e descrever o conceito.

### Nível 2 — Reproduzir
Consegue implementar exemplos semelhantes aos estudados.

### Nível 3 — Aplicar
Consegue resolver problemas novos usando o conceito.

### Nível 4 — Analisar
Consegue comparar soluções, identificar falhas e justificar decisões.

### Nível 5 — Construir
Consegue integrar vários conceitos num sistema funcional.

### Nível 6 — Projetar
Consegue definir arquitetura, requisitos, testes, segurança, observabilidade e manutenção.

## Regra de progressão

Não usar apenas tempo estudado ou quantidade de ficheiros como medida de progresso.

A progressão deve considerar:

**conhecimento + prática + autonomia + qualidade + capacidade de diagnóstico.**

## Portfólio

Ao terminar cada grande nível, deve existir pelo menos um artefacto que possa ser revisto posteriormente.

O portfólio final deverá demonstrar evolução desde programas simples até sistemas completos.
